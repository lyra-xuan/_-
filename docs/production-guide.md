# 制作思路与监督指南

## 推荐制作思路

优先完成一局从开始到结束的短流程，再打磨演示效果。核心顺序是：

1. **范围定稿**：确认玩法主题、游戏时长、胜负条件和素材风格。
2. **玩法闭环**：标题页、玩家攻击、Boss、胜负与重开。
3. **碰撞展示**：命中/擦弹双层判定、相对运动扫掠、测试与可视化。
4. **视觉反馈**：弹幕颜色与轨迹、命中反馈、阶段提示、HUD。
5. **验收打包**：新建环境安装依赖，按 README 启动，完成演示流程。

一次只推进一个可运行的小功能，避免同时重写玩法、架构和美术。

## 建议里程碑

| 里程碑 | 可见结果 | 你需要确认 |
|---|---|---|
| A. 范围与素材方向 | 一页需求确认、素材清单 | 题材、玩法规模、素材来源 |
| B. 操作与碰撞 | 玩家可移动，能稳定触发命中/擦弹 | 手感、判定范围是否易理解 |
| C. 攻击与 Boss | 已实现玩家射击、Boss 三段符卡、掉落道具、血条与胜利重开 | 你确认难度、弹速和密度 |
| D. 游戏闭环 | 开始、胜利/失败、重开 | 一局时长和结束体验 |
| E. 演示打磨 | HUD、特效、说明书、背景音乐与干净启动 | 视觉风格、演示顺序 |

每个里程碑交付后，你只需运行一次并反馈：**通过 / 哪里不舒服 / 希望改成什么**。不需要审读全部源码。

## 你可以怎样监督制作

- 看游戏而不是先读代码：是否能启动、按键是否符合预期、失败后是否能重开。
- 每次只给一个主要反馈，例如“弹幕太密”或“擦弹提示不明显”。
- 对算法展示，重点检查能否现场说明：玩家判定圆、擦弹圆、为什么用扫掠检测、网格怎样减少候选。
- 对素材，确认画面原创且来源许可清楚；不满意时先改风格方向，再批量制作。
- 代码审核采用轻量模式：常规改动跑相关测试并做一次自查；碰撞核心、状态流转或大型重构时再启动独立审查。

## 当前协作节奏

一个功能块完成后：实现 → 运行/测试 → 简短说明改动和验证结果 → 提交 Git。只有核心算法或风险较高的改动才额外安排独立审查；审核发现的问题再决定是否修复。

## 范围确认状态

已确认：

- 规模：三关推进（杂兵波次 → 中 Boss → 关底 Boss + 符卡 → 关卡结算），含掉落道具与灵击。
- 视觉方向：参考东方幻想弹幕风格，说明书与 HUD 采用哥特描金配绯红。
- 素材策略：使用用户提供并确认许可的东方红魔乡图片与音效，以及东方音乐包中的 PC-98 原曲转码的背景音乐。

已落地：标题页与说明书（背景说明 / 用语解说 / 操作指南三页）、三关战斗流程与立绘对话、音效与循环背景音乐。素材来源与许可分别登记在 `assets/title/ATTRIBUTION.md`、`assets/gameplay/ATTRIBUTION.md`、`assets/audio/ATTRIBUTION.md` 和 `assets/bgm/ATTRIBUTION.md`；非商业用途本身不等于获得许可，详见 [素材需求](assets.md)。
