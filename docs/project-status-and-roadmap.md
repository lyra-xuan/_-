# 项目现状与后续制作路线

更新日期：2026-11-13

本文用于后续制作交接，记录当前项目完成情况、V1 验收缺口和可选扩展方向。状态以本文件更新日期的代码、文档和测试为准。

## 项目目标

- 使用 Python + pygame-ce 制作单人 2D 弹幕射击游戏，不使用成熟游戏引擎。
- 规模限定为一关一 Boss，突出碰撞检测的实现与可视化演示。
- 视觉与术语参考东方 Project；本项目是课程演示版，不以完整复刻 TH06 为 V1 验收目标。
- 当前工作目录：`my-game`；参考工程：同级目录 `project-striker`。

## 已完成内容

### 可玩流程

- 标题页可进入游戏、打开三页说明书或退出。
- 玩家可移动、低速移动和连续射击；火力成长后弹数增加。
- Boss 有三段攻击：瞄准扇形、双层环形和旋转螺旋加散射。
- 玩家有三条命；受击后清屏、重生并获得短暂无敌时间。
- 妖精可被击破并掉落道具；Boss 阶段转换也会掉落道具。
- 支持胜利战绩、后记、鸣谢；失败可重开或返回标题。
- 最高分以 `hiscore.txt` 保存，但目前只在胜利路径检查，详见下方缺口。

### 碰撞检测与测试

- `src/collision.py`：AABB、圆-圆、点-圆、线段-圆检测和 `SpatialGrid`。
- 玩家与敌弹使用相对运动扫掠检测；擦弹和致命命中使用不同判定半径。
- 玩家弹与 Boss/妖精的碰撞也考虑双方位移。
- 测试覆盖几何边界、实体、碰撞扫掠、Boss、道具、装饰、美术和音频降级。

### 主要入口

- `src/game.py`：游戏状态、输入、战斗、碰撞、道具、计分和 UI。
- `src/entities.py`：玩家、敌弹、玩家弹、Boss、妖精和道具实体。
- `src/config.py`：窗口、速度、判定、弹幕、计分和道具参数。
- `src/audio.py`：音效和场景 BGM 加载，失败时静默降级。

## V1 验收缺口与文档问题

以下事项属于当前一关一 Boss 范围内，应在宣布 V1 验收完成前处理。

### P1：道具拾取方式与验收标准不一致

验收标准写明“道具可被射击或吸附拾取”，但当前实现是道具下落、进入范围后磁吸、接触自机后收集；玩家弹不会与道具交互。

- 代码位置：`src/game.py` 的 `_collect_item()`、`_update_items()`；玩家弹碰撞目前只处理 Boss 和妖精。
- 决策：若“射击拾取”是期望玩法，实现对应交互并补充测试；若不是，修订 `docs/requirements.md` 的验收文字。
- 完成标准：实现与需求文字一致，且 POWER、POINT、LIFE 的拾取效果均有测试覆盖。

### P1：失败局新高分不会持久化

`_register_hiscore()` 当前由 Boss 击败路径调用。玩家在失败前取得的新高分不会被写入 `hiscore.txt`，与“得分超过历史最高分时写入”的验收要求不一致。

- 代码位置：`src/game.py` 的 `_on_boss_defeated()`、`_register_hiscore()` 和 `_on_player_hit()`。
- 建议：在本局结束结算时统一检查高分，覆盖胜利和失败；避免每次得分变化都重复写盘。
- 完成标准：新增测试证明胜利局和失败局的新高分都会保存，未超过历史高分时不会覆盖。

### P2：需求文档的 BGM 数量过时

`docs/requirements.md` 当前写“三首循环背景音乐”，而 `src/audio.py` 映射了标题、关卡、Boss、结局四个场景。统一文档口径，并确认四个 OGG 文件均存在。

### P2：缺少人工完整流程验收记录

自动化测试通过不代表画面、按键和音频在实际运行时都已验收。建议使用 Python 3.12 环境，按 README 启动后完成以下检查：

- 标题进入、说明书翻页、返回标题。
- 开场卡、移动、低速、射击、暂停/继续，分别检查四个场景的 BGM 切换。
- F2 调试层、F3 无敌切换和 HUD 状态。
- 三段攻击、命中/擦弹、道具拾取、阶段转换与超时。
- 失败后重开/返回标题；胜利后战绩、后记、鸣谢翻页。

建议将人工检查日期、环境和结果补充在本文件末尾或项目验收记录中。

1. 按上方流程清单实际启动并走完一局。

### 阶段 C：可选的 TH06 玩法靠拢

仅当项目目标从课程演示扩展为原作玩法还原时再排期，不作为当前 V1 阻塞项：

- 炸弹/符卡释放、消弹、伤害与无敌效果。
- 更接近原作的 POWER 等级与受击后火力损失。
- POINT 道具价值和收集高度、擦弹及符卡捕获奖励之间的计分循环。
- 角色/射击类型选择、关卡流程、普通攻击与符卡交替。
- 明确区分“符卡限时结束”和“Boss 被击破”；当前最后阶段超时会直接判胜，是本项目自定义简化规则。

TH06 有多关流程、角色与射击类型、炸弹、POWER/POINT 资源循环及符卡捕获奖励。当前项目只选取低速移动、擦弹、符卡分段等概念，不是完整复刻。玩法参考：[Touhou Wiki - Embodiment of Scarlet Devil: Gameplay](https://touhou.fandom.com/pt/wiki/Embodiment_of_Scarlet_Devil:_Gameplay)。

## 与 project-striker 的定位差异

`project-striker` 是更完整的 STG 参考工程，包含多关卡脚本、多个机体/射击配置、炸弹或 Hyper、道具、Replay 和更丰富的结算系统。当前项目刻意采用更小的单 Boss 范围，把课程核心放在碰撞算法、扫掠检测和调试展示。

因此，当前 V1 不应因没有 Replay、多机体或多关卡而判定未完成；只有当后续目标明确改为完整 STG 或 TH06 还原时，才把这些系统纳入新范围。
